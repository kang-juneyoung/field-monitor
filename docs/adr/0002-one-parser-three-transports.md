# 0002. 파서 하나, 수신 경로 셋

**상황** 같은 장비라도 현장에 따라 RS-232C 직결, 무선 모뎀(UDP), 게이트웨이(TCP)로 들어온다.
경로마다 파서를 따로 두면 검증 규칙이 어긋난다.

**결정**
- 프레임 형식은 하나: `$POS,<id>,<lat>,<lon>,<km/h>,<deg>*<XOR 체크섬>` (NMEA 0183 문장 구조).
- 수신기는 "바이트 → 줄" 까지만 책임지고, 줄을 `sink(line, source)`로 넘긴다. 검증은 `decode_pos` 한 곳.
  - UDP: 데이터그램 하나에 여러 줄이 올 수 있어 줄 단위로 나눈다.
  - TCP: 스트림이라 프레임이 쪼개져 오거나 붙어 온다 → `readline()`으로 줄 경계에서만 자른다.
    줄바꿈 없이 512바이트를 넘기면 비정상 스트림으로 보고 연결을 끊는다(메모리 보호).
  - 시리얼: pyserial은 블로킹 I/O라 별도 스레드에서 읽고 `call_soon_threadsafe`로 이벤트 루프에 넘긴다.
    포트가 사라지면(케이블 분리) 3초마다 다시 연다.
- 오류 프레임(체크섬·형식·범위)은 버리되 경로별로 센다. 이벤트 로그(최초 수신·두절·복구)와 분리해,
  오류가 많아도 중요한 상태 변화가 화면에서 밀려나지 않게 한다.
- 통신 두절은 "N초 동안 수신 없음"으로 판단한다(기본 5초, `FIELD_LOST_AFTER`).
