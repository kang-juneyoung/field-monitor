# 0003. 수신 기록과 재생으로 통신 이상을 재현한다

**상황** 통신 이상(두절, 잡음으로 깨진 프레임, 중복 수신)은 현장에서만 가끔 생긴다.
사무실에서 같은 상황을 다시 만들 수 없으면 수정이 맞는지 확인하기 어렵다.

**결정**
- 서버는 받은 줄을 오류 프레임까지 포함해 JSON Lines로 그대로 기록한다(`logs/recordings/`).
  시각은 기록 시작 후 경과 초(단조 시계)로 남겨 시스템 시각 변경에 흔들리지 않게 한다.
- `tools/replay.py`는 기록을 원래 간격대로 다시 보내면서 이상을 주입한다.
  - `--drop UNIT:시작-끝` 특정 장비를 구간 동안 끊는다
  - `--corrupt 비율` 체크섬을 깨뜨린다, `--dup 비율` 같은 프레임을 두 번 보낸다
  - `--speed` 배속, `--via udp|tcp` 경로 고정, `--seed` 난수 고정
- 재생 계획(`plan`)은 순수 함수로 분리했다. 같은 기록·옵션·seed면 결과가 항상 같아 단위 테스트가 가능하다.

**결과** "현장 기록 한 개 + 재생 옵션 한 줄"로 문제 상황을 팀원 누구나 똑같이 재현할 수 있다.
끝에서 끝까지 시험(`test_replay_end_to_end_into_tracker`)은 재생 → 실제 소켓 수신 → 두절 판정까지 확인한다.
